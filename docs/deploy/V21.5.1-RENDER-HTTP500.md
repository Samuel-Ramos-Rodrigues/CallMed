# CallMed V21.5.1 — correção HTTP 500 no Render

## Causa
O log do Render mostrou esgotamento do limite Linux de `inotify`/descritores durante a geração de versão automática de arquivos estáticos pelo Razor (`DefaultFileVersionProvider`). O gatilho era o uso repetido de `asp-append-version=\"true\"` em CSS, JavaScript e imagens.

## Correção
1. Todos os `asp-append-version` foram removidos das Views.
2. Assets locais receberam cache-busting fixo `?v=2151`.
3. O Dockerfile define `DOTNET_USE_POLLING_FILE_WATCHER=1`.
4. O Dockerfile define `DOTNET_HOSTBUILDER__RELOADCONFIGONCHANGE=false`.
5. O Service Worker recebeu novo cache `callmed-static-v21-5-1-render-inotify-fix`.

Isso elimina a chamada de `DefaultFileVersionProvider.AddFileVersionToPath` que estava derrubando a renderização das Views.
